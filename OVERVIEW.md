# Описание проекта — CEO-дашборд производственной компании

Мини-документация для передачи проекта. Отвечает на три вопроса: **что это**, **что показывает**, **откуда берутся данные**.
Для запуска и онбординга — см. [README.md](README.md) и [HANDOFF.md](HANDOFF.md).

---

## 1. Суть

Это **финансовый дашборд для собственника** производственной компании (валюта RSD). Он берёт управленческий учёт из сервиса **ПланФакт** (app.planfact.io) и показывает его в одном удобном экране: сколько денег, кто кому должен, прибыльно ли работаем, как идут проекты.

Два ключевых принципа:
- 🔴 **API ПланФакта — только чтение.** Дашборд ничего не создаёт и не меняет в ПланФакте. Все правки собственник делает вручную в самом ПланФакте. См. [DECISIONS.md](DECISIONS.md) #1.
- 📸 **Дашборд — «фотография» данных на момент обновления.** Он не считает учёт заново, а показывает то, что уже посчитано в ПланФакте (сверено с родными отчётами до рубля).

## 2. Что показывает (по разделам)

Меню слева. Валюту (RSD/EUR) и обновление данных — там же, в сайдбаре.

### 🏠 Главный
- **KPI:** деньги на счетах, дебиторка, кредиторка, прибыль с апреля.
- **Остатки по счетам** — основные счета (DOO Осн 51, DOO Доп 82, КЭШ) + поле «факт из банка» (ручная корректировка на задержку банк-клиента).
- **Продажи по категориям** — помесячно/поквартально, переключатель **«продано по договорам» (начисление) / «получено фактически» (касса)**, строка «Заказчик должен доплату».
- **План продаж** — кольцевые диаграммы план/факт по категориям, прогноз по темпу; план правит собственник (сохраняется на сервер, виден всем).

### 📊 P&L маржинальный (ОПУ)
Отчёт о прибылях и убытках методом начисления, помесячно: Выручка → Переменные → **Маржинальная прибыль** → Постоянные → Прочие → Амортизация → Проценты → Налог → **Чистая прибыль** → Дивиденды → Нераспределённая. Каждая строка раскрывается в подстатьи. **Сходится с родным ОПУ ПланФакта до рубля.**

### 📉 Кредиторка
Кому и сколько мы должны (начислено, но не оплачено), сгруппировано **по контрагентам**, разложено по неделям (просрочено / текущая неделя / +6 недель / позже). Есть **поиск по контрагенту**, фильтр «вся / просроченная», и:
- **Режим одобрения платежей** → отмечаешь, что платим (всю сумму или часть) → «Применить» формирует **реестр платежей** (с датой-временем), который можно скачать в PDF и распечатать. Реестры хранятся во вкладке **«Реестры»**, когда все платежи проведены в ПланФакте — реестр становится архивом.

### 💧 ДДС
Движение денежных средств (кассовый метод) по видам деятельности: операционный / инвестиционный / финансовый поток, помесячно, + чистый поток и остаток на счетах.

### 🗂 Проекты
Прибыльность по проектам (заказам) методом начисления: доходы / расходы / прибыль / рентабельность. Проекты сгруппированы **по месяцу начала** (спец-папки ПланФакта вроде «Платные Замеры» — отдельно). Раскрытие проекта показывает неоплаченные начисления (дебиторку 🟢 и кредиторку 🔴).

## 3. Откуда берутся данные

### Поток
```
ПланФакт API ──(fetch_data.py, ТОЛЬКО ЧТЕНИЕ)──> dashboard/data/dashboard.json ──(build.py)──> dashboard/index.html
```
- `dashboard/fetch_data.py` — единственная точка обращения к API. Читает ключ из `.env`, тянет данные, считает агрегаты, пишет `dashboard.json`. **Ключ в вывод/JSON не попадает.**
- `dashboard/build.py` — рендер самодостаточного `index.html` (данные вшиты в страницу).
- «Обновить» = заново прогнать эти два скрипта.

### Какие эндпоинты ПланФакта питают что (всё — чтение)
| Раздел дашборда | Источник в ПланФакте |
|---|---|
| KPI, остатки по счетам | `GET /accounts`, `GET /bizinfos/accountshistory` |
| Продажи, P&L, кредиторка, проекты | `POST /operations/list` (Income/Outcome) + `GET /operationcategories` (классификация статей) |
| ДДС | помесячные агрегаты потоков (кассовый метод) |
| Проекты | `GET /projects` (папка, статус) + операции |
| План продаж | `dashboard/plans.json` (правится собственником) |

### Ключевые определения (важно понимать)
- **Начисление vs касса.** У операции две даты: **дата начисления** (когда доход/расход признан — для P&L) и **дата оплаты** (когда деньги прошли — для ДДС). P&L считается по начислению, ДДС — по оплате.
- **Дебиторка** = продано, но деньги не получены. **Кредиторка** = начислено, но не оплачено.
- Подробнее по расчётам — в [ARCHITECTURE.md](ARCHITECTURE.md), раздел «Ключевые определения».

### Где это живёт (Фаза 2 — задеплоено)
- **Веб-версия** на **Railway** (Flask, `app.py`): дашборд за логином/паролем, кнопка «Обновить» (серверный `/refresh`) и автообновление ежедневно в 10:00. Адрес и переменные — в [DEPLOY.md](DEPLOY.md).
- **Supabase** (проект servicebot) хранит общие данные: **реестры одобрения платежей** и **общие настройки** (план, валюта, порядок меню, ручной остаток банка) — чтобы были одинаковыми у всех, кто заходит.
- **Ключи** (ПланФакт, Supabase service-key, логин/пароль) — только в переменных окружения сервера, в браузер не попадают.

## 4. Что нужно новому сотруднику
- Свой **API-ключ ПланФакта** (у каждого свой) → в `.env`. Ключ предыдущего не передаётся.
- **Код лежит в самой папке** — это самодостаточный проект (только Python 3, без внешних пакетов). Подключаться к чужому GitHub не обязательно: GitHub — лишь копия папки + история версий. Для локальной работы достаточно папки + своего ключа. Подробнее (папка / GitHub / Railway) — [HANDOFF.md](HANDOFF.md), раздел 0.
