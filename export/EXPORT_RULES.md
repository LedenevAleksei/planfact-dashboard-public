# Правила экспорта операций ПланФакт — канонический свод

Единый источник правды по экспорту/бэкапу операций. К этому файлу возвращаемся при каждом
экспорте и **дополняем его новой информацией** (см. раздел «Журнал» внизу).
Правила закодированы в скриптах — здесь их человекочитаемое описание + находки и каверзы.

> 🔴 Экспорт — это **только чтение** из API ПланФакта (Правило №1 проекта). Импорт обратно
> делает человек через родной импорт ПланФакта, не через API.

---

## 1. Два вида экспорта

| Скрипт | Что делает | Куда пишет |
|---|---|---|
| `dashboard/export_operations.py` | **универсальный бэкап**: все поля, гибко | `export/` (xlsx+csv на квартал, 29 колонок, + `operations_full.json` — полный без потерь) |
| `dashboard/export_for_planfact.py` | **под импорт в ПланФакт**: строго по шаблону | `export/planfact_import/` (xlsx+csv на квартал по 20 колонкам шаблона) |

Запуск (нужен `openpyxl` для xlsx; без него — только csv/json):
```bash
python3 dashboard/export_operations.py
python3 dashboard/export_for_planfact.py
```
Ключ берётся из `.env` (`PLANFACT_API_KEY`). Папка `export/` — в `.gitignore` (данные не коммитим),
кроме этого файла правил.

---

## 2. Источник данных

- `POST /api/v1/operations/list` с `operationType` = Income / Outcome / **Move** — все три вызова обязательны.
- Справочник статей: `GET /api/v1/operationcategories` (для `accountCategoryType`, `outcomeClassification`, родительских статей).
- **Пагинации нет** — endpoint отдаёт всё за один вызов (`data.total`=0, все в `data.items`).
- Группировка по кварталам — по **дате платежа** (`operationDate`).

---

## 3. Формат импорта ПланФакта (шаблон `PlanFactCashflowTemplate.xlsx`, лист «Операции»)

**20 колонок в строгом порядке:**
`Дата оплаты` · `Статус оплаты` · `Дата начисления` · `Статус начисления` · `Контрагент` ·
`ИНН контрагента` · `Тип` · `Счет` · `№ Счета` · `Банк` · `Бик` · `Юрлицо` · `ИНН юрлица` ·
`Статья` · `Родительские статьи` · `Вид деятельности` · `Назначение платежа` · `Проекты` · `Сумма` · `Валюта`

**Обязательные (оливковые в шаблоне):** Дата оплаты · Тип · Счет · Юрлицо · Сумма.

**Правила:**
- **Тип** = `Поступление` / `Выплата` / `Перемещение`.
- **Сумма СО ЗНАКОМ:** Поступление / Зачисление = «+», Выплата / Списание = «−».
- **Статусы** отдельными колонками: `Статус оплаты`, `Статус начисления` = `Подтверждена` / `Не подтверждена`.
  Даты при этом заполняются всегда (неоплаченные помечаются статусом, а не пустой датой).
- **Перемещение = ДВЕ строки подряд:** сначала счёт списания со статьёй `[Списание]` (−),
  сразу под ней — счёт зачисления со статьёй `[Зачисление]` (+). Обе строки: Тип=`Перемещение`,
  без контрагента/начисления/проекта/вида деятельности.
- **Проекты** в формате `Название (100%)`.
- **Вид деятельности** (перевод из API): `Operating`→`Операционная деятельность`,
  `Finance`→`Финансовая деятельность`, `Investment`→`Инвестиционная деятельность`.
- **Даты** в формате `ГГГГ-ММ-ДД 00:00:00`.
- **Без формул**, сохранять только в **XLSX** (XLS не поддерживается).
- Импорт: ПланФакт → Операции → Импорт → файл квартала.

---

## 4. Особенности данных проекта

- **Перемещения хранятся как пара Income+Outcome** на статье «Переводы в пути», связанные через
  `boundMoveOperationId`. Отдельного `operationType == "Move"` в самих операциях нет — «Move» это
  только фильтр `operations/list`. Списание = Outcome-нога, зачисление = Income-нога.
- **Суммы в API положительные** (`value` / `valueInUserCurrency`), знак задаём сами по типу.
- **Вид деятельности** приходит по-английски (на уровне `operationParts[].operationCategoryActivityType`).
- **ИНН, № счёта, Банк, Бик — в API отсутствуют** (Сербия: там PIB, не ИНН). В файлах эти колонки пустые.
- **Валюта учёта — RSD** (все счета RSD; `account.currencyCode`).
- **Проект «Не выбран» / `isUndistributed`** → колонка «Проекты» пустая.

---

## 5. Каверзы и ограничения (проверять на предпросмотре импорта)

- **Неоплаченные** (`isCommitted=false`, ~128 операций) → «Статус оплаты» = «Не подтверждена».
  Это дебиторка/кредиторка — не должны стать оплаченными.
- **Разбитые на статьи** (~9 операций) → каждая часть отдельной строкой → импортируются как
  отдельные операции (суммы сохраняются, структура «одна операция, N статей» — нет).
- **Дедуп при импорте в непустой аккаунт** — ПланФакт на предпросмотре покажет дубли; для чистого
  аккаунта неактуально. Ключ идемпотентности при желании — по `externalId`/сумме+дате.
- Всегда **сначала тестировать один маленький квартал** (напр. `import_2023-Q3.xlsx`) и смотреть превью.

---

## 6. Порядок безопасного возврата к бэкапу в ПланФакт
1. Скачать актуальный шаблон в ПланФакте и сверить заголовки колонок.
2. Прогнать `export_for_planfact.py`.
3. Импортировать один квартал → проверить превью (переводы, статусы, статьи/проекты/контрагенты).
4. Импортировать остальные кварталы.
